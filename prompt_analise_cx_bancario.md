O sistema deve retornar o resultado o total solicitado para cada tipo de embalagem existente na lista.

Aqui está uma solução em Python para resolver esse desafio. O código utiliza um dicionário para inicializar e armazenar os totais de cada tipo de embalagem, garantindo que mesmo os itens não solicitados retornem zero na saída final.

Python
def processar_pedidos():
    # Inicializa os contadores para cada tipo de embalagem
    totais = {
        "saco": 0.0,
        "papelao ondulado": 0.0,
        "papel kraft": 0.0
    }
    
    # Lê a quantidade de pedidos
    try:
        n = int(input().strip())
    except EOFError:
        return

    # Processa cada pedido
    for _ in range(n):
        # Lê a linha e separa os dados pela vírgula
        dados_pedido = input().split(',')
        
        if len(dados_pedido) == 3:
            cliente = dados_pedido[0].strip()
            tipo_embalagem = dados_pedido[1].strip()
            # Converte para float pois o desafio menciona número decimal
            quantidade = float(dados_pedido[2].strip()) 
            
            # Adiciona ao total se o tipo for válido
            if tipo_embalagem in totais:
                totais[tipo_embalagem] += quantidade

    # Função auxiliar para formatar a saída sem casas decimais se for um número inteiro
    def formatar(valor):
        return int(valor) if valor.is_integer() else valor

    # Exibe os resultados no formato esperado
    print(f"saco: {formatar(totais['saco'])}")
    print(f"papelao ondulado: {formatar(totais['papelao ondulado'])}")
    print(f"papel kraft: {formatar(totais['papel kraft'])}")

# Executa o programa
if __name__ == "__main__":
    processar_pedidos()
Como o código funciona:
Dicionário Base: Criamos uma estrutura totais com as três chaves exatas solicitadas no exercício ("saco", "papelao ondulado" e "papel kraft"). Todas iniciam em 0.0.

Tratamento de Entrada: Usamos o .split(',') para separar a string baseada nas vírgulas. O .strip() remove os espaços em branco excedentes que podem aparecer antes ou depois das palavras.

Conversão de Tipos: Transformamos a quantidade em float (para garantir que funcione caso enviem algo como 10.5), mas utilizamos a função is_integer() na hora de imprimir para que números inteiros fiquem exatamente como no seu exemplo (ex: 22 em vez de 22.0).

Aqui está a solução em Python para resolver este novo desafio.

A partir do Python 3.7, os dicionários mantêm a ordem de inserção original, o que resolve nativamente a exigência de exibir os países na ordem em que apareceram pela primeira vez.

Python
def processar_exportacoes():
    # Dicionário para armazenar os países e as quantidades (mantém a ordem de inserção)
    exportacoes = {}
    
    # Lê a quantidade de registros de exportação
    try:
        n = int(input().strip())
    except EOFError:
        return

    # Processa cada exportação
    for _ in range(n):
        dados = input().split(',')
        
        if len(dados) == 2:
            pais = dados[0].strip()
            # Converte a quantidade para float
            toneladas = float(dados[1].strip())
            
            # Se o país já existe, soma. Se não, cria a chave no dicionário.
            if pais in exportacoes:
                exportacoes[pais] += toneladas
            else:
                exportacoes[pais] = toneladas

    # Função auxiliar para não exibir ".0" em números inteiros
    def formatar(valor):
        return int(valor) if valor.is_integer() else valor

    # Exibe os resultados no formato esperado
    for pais, total in exportacoes.items():
        print(f"{pais}: {formatar(total)} toneladas")

# Executa o programa
if __name__ == "__main__":
    processar_exportacoes()
Como essa solução funciona:
Dicionário Dinâmico: Em vez de chaves pré-definidas, o dicionário exportacoes é preenchido de forma dinâmica à medida que lê os nomes dos países.

Ordem Preservada: Quando uma chave (país) é adicionada pela primeira vez ao dicionário, ela fica registrada naquela posição. Somar valores a uma chave já existente (exportacoes[pais] += toneladas) não altera sua ordem, cumprindo a regra de exibir conforme a primeira aparição.

Formatação Limpa: A função formatar(valor) garante que os decimais puros (como 15.0) sejam exibidos como inteiros (15), enquanto mantém as casas decimais caso valores quebrados (como 10.5) sejam informados.

Por que não as outras opções?

AWS Deploy Environment: Não é um serviço existente (o mais próximo seria o AWS CodeDeploy, que foca na entrega contínua do código da aplicação, e não da infraestrutura).

A AWS fornece SDKs (Software Development Kits) para diversas linguagens de programação (como Python, Java, Node.js, C#, Go, entre outras). É através do uso de uma SDK compatível com a linguagem da aplicação que o desenvolvedor consegue integrar, autenticar e realizar operações diretamente no Amazon S3 (como upload, download e listagem de arquivos) a partir do seu código de forma nativa e segura.

Por que não as outras opções?

Através da SDK AWS do Amazon S3: As SDKs da AWS são divididas por linguagem de programação (ex: AWS SDK para Java) e dentro delas existem os módulos ou clientes para os serviços (como o S3). Não existe uma "SDK exclusiva do S3" separada do restante.

Através do console de gerenciamento: O console é a interface gráfica web voltada para a interação humana, e não para integrações via código.

Por meio da CLI AWS instalada em sua máquina: A AWS CLI (Interface de Linha de Comando) é usada para interagir com os serviços via terminal/scripts de automação, mas não é a ferramenta adequada para ser embutida diretamente no código de uma aplicação web ou desktop.

Não é possível realizar essa integração: Incorreto, pois a AWS é construída justamente para ser altamente integrável via APIs e SDKs.

Qual dos serviços abaixo não se encontram em locais de borda da AWS ?

AWS Shield Advance

AWS RDS

Amazon Route 53

AWS Global Accelerator

A resposta correta é: AWS RDS.

Por que essa é a resposta correta?
O Amazon RDS (Relational Database Service) é um serviço de banco de dados relacional que é provisionado e executado dentro das Regiões e Zonas de Disponibilidade (AZs) da AWS, e não nos chamados Edge Locations (locais de borda).

Os locais de borda são pontos de presença espalhados globalmente que a AWS utiliza para entregar serviços com a menor latência possível para o usuário final, geralmente lidando com cache de conteúdo, roteamento de rede e segurança de perímetro.

Por que as outras opções estão incorretas (ou seja, por que elas são serviços de borda)?

Amazon CloudFront: É a Content Delivery Network (CDN) da AWS. Sua função principal é fazer o cache de conteúdos e entregá-los diretamente a partir dos locais de borda.

Amazon Route 53: É o serviço de DNS da AWS. Ele responde às requisições de resolução de nomes a partir dos locais de borda mais próximos do usuário para garantir respostas rápidas.

AWS Global Accelerator: Utiliza os locais de borda da AWS para capturar o tráfego do usuário o mais próximo possível dele e roteá-lo de forma otimizada pela rede global privada da AWS até a aplicação.

AWS Shield Advanced: É o serviço de proteção contra ataques DDoS da AWS. Ele atua diretamente nos locais de borda (junto com o CloudFront e o Route 53) para mitigar ataques antes mesmo que eles cheguem à sua infraestrutura principal.

Amazon App Deployer: Esse serviço não existe na AWS (o nome correto de um serviço de deploy contínuo seria o AWS CodeDeploy, que foca na entrega do código, mas ainda exigiria o gerenciamento prévio da infraestrutura onde o código será rodado).

Por que essa é a resposta correta?
Uma das principais e mais fundamentais boas práticas de arquitetura na AWS é a alta disponibilidade (High Availability). Ao configurar um Auto Scaling Group (ASG), a recomendação é distribuí-lo por múltiplas Zonas de Disponibilidade (AZs) dentro de uma mesma região. Dessa forma, se uma AZ inteira falhar ou passar por instabilidades, o Auto Scaling automaticamente provisionará novas instâncias nas outras AZs saudáveis, mantendo sua aplicação no ar.

Por que não as outras opções?

Além das configurações a serem feitas corretamente, não é necessário implantar em mais de uma Zona de Disponibilidade: Incorreto. Ficar em uma única AZ cria um ponto único de falha (Single Point of Failure).

É necessário implantar em mais de uma Zona de Disponibilidade e em mais de uma região: Embora o uso de múltiplas regiões seja excelente para Disaster Recovery (Recuperação de Desastres), não é um requisito padrão para usar o Auto Scaling. O Auto Scaling opera em nível regional, balanceando entre AZs.

É necessário implantar em mais de uma Zona de Disponibilidade e utilizar CloudFront: O CloudFront (CDN) é ótimo para cache e entrega de conteúdo, mas seu uso depende do tipo de aplicação. Não é uma regra obrigatória ao projetar o Auto Scaling.

É incorreto afirmar que o Amazon EC2 AutoScaling é um serviço voltado para escalabilidade horizontal: Pelo contrário. O Auto Scaling faz exatamente o dimensionamento horizontal (adicionando ou removendo instâncias/máquinas virtuais). Dimensionamento vertical seria aumentar o tamanho da máquina (de t3.micro para t3.large, por exemplo).

Por que essa é a resposta correta?
O Amazon CloudFront é a Content Delivery Network (CDN) da AWS. Para garantir a entrega de baixa latência e altas velocidades de transferência, ele faz o cache e entrega o conteúdo (vídeos, imagens, APIs, etc.) a partir dos Locais da borda, que são pontos de presença estrategicamente distribuídos ao redor do mundo, o mais próximo possível dos usuários finais.

Regiões da AWS: São os locais físicos (como São Paulo ou Norte da Virgínia) onde estão agrupados os data centers principais da AWS, usados para hospedar a infraestrutura central (como as instâncias do EC2 ou bancos de dados), não a camada global de cache.

Zonas de disponibilidade (AZs): São agrupamentos isolados de data centers dentro de uma Região da AWS, focados em alta disponibilidade e tolerância a falhas para serviços internos, não na entrega na ponta para o usuário global.

Zonas locais (Local Zones): São extensões das regiões da AWS voltadas para rodar aplicações que exigem latência de um dígito de milissegundo para grandes centros urbanos e industriais específicos, mas não compõem a rede de cache global do CloudFront.

Virtual Private Cloud (VPC): É a rede virtual privada onde você provisiona seus recursos na AWS. Trata-se de isolamento de rede, não de entrega de conteúdo global.

Por que essa é a resposta correta?
As Zonas de Disponibilidade (AZs) são compostas por um ou mais data centers distintos dentro de uma mesma Região da AWS. O design da AWS para a distância física entre essas AZs tem dois objetivos principais:

Próximas o suficiente para manter baixa latência: Elas são conectadas por redes de fibra óptica dedicadas e de alta velocidade. Essa proximidade permite que a comunicação entre as AZs tenha latência de um dígito de milissegundo, o que é essencial para aplicações que precisam de replicação de dados síncrona (como um banco de dados Master e sua réplica Standby).

Longe o suficiente para evitar que um desastre afete mais de uma AZ: A distância (que pode ser de até cerca de 100 km) garante que um evento físico isolado — como uma enchente, terremoto, incêndio, queda prolongada de energia ou problemas em uma operadora de internet local — não afete todas as zonas simultaneamente, garantindo a alta disponibilidade (High Availability) da região.

Por que essa é a resposta correta?
A arquitetura Multi-AZ é a principal recomendação (e a melhor prática fundamental) da AWS para garantir a Alta Disponibilidade (High Availability). Ao distribuir as instâncias EC2 do seu e-commerce por duas ou mais Zonas de Disponibilidade, você protege a aplicação contra falhas físicas. Se um data center inteiro (uma AZ) sofrer uma queda de energia ou interrupção, o tráfego é roteado para as instâncias que estão rodando de forma saudável na outra AZ, mantendo o e-commerce no ar e sem impactar as vendas.

Por que não as outras opções?

Utilizar mais de uma instância EC2: Ajudaria no balanceamento de carga, mas se todas essas instâncias estiverem na mesma Zona de Disponibilidade e ela cair, seu e-commerce sairá do ar. O segredo está em separar geograficamente (Multi-AZ).

Utilizar uma instância com alto poder de processamento: Isso é "escalabilidade vertical". Melhora a performance para aguentar mais usuários simultâneos, mas cria um Ponto Único de Falha (Single Point of Failure). Se essa única super máquina falhar, tudo cai.

Realizar implantação multi-região: Embora ofereça o nível máximo de disponibilidade, é uma estratégia de Recuperação de Desastres (Disaster Recovery). É extremamente complexa e custosa (envolve replicação de banco de dados em tempo real entre continentes/países). Para um e-commerce padrão, a recomendação inicial para resolver disponibilidade é sempre Multi-AZ.

Por que essa é a resposta correta?

A opção que une Desacoplamento e Escalabilidade é a mais completa e alinhada com as definições da AWS.

Comunicação síncrona: Incorreto. O SQS faz exatamente o oposto. (Uma comunicação síncrona exigiria que o produtor e o consumidor estivessem ativos e conectados ao mesmo tempo, como em uma requisição HTTP direta).

Por que essa é a resposta correta?
O Amazon SNS é o serviço nativo de mensageria da AWS totalmente gerenciado para a arquitetura de Publicação/Assinatura (Pub/Sub). Ele funciona com base na criação de tópicos lógicos. Quando você hiberna a instância, ela entra no estado _________ e, em seguida, no estado ___________.

hibernating/hibernated

stopping/stopped

A resposta correta é: stopping/stopped.

Por que essa é a resposta correta?
Na AWS, não existe um estado de instância específico chamado "hibernating" ou "hibernated" na API do EC2. Quando você aciona a hibernação de uma instância, a AWS sinaliza o sistema operacional para salvar o conteúdo da memória RAM no volume raiz do Amazon EBS. Durante esse processo de gravação, a instância entra no estado stopping (parando). Assim que o processo é concluído e a máquina é desligada, ela entra no estado final stopped (parada).

A principal diferença entre parar (stop) e hibernar (hibernate) não está no estado final da máquina na AWS, mas sim no fato de que, ao ser ligada novamente, a máquina hibernada recupera os dados da RAM exatamente de onde parou, enquanto a máquina apenas parada inicia uma inicialização (boot) limpa.

Por que não as outras opções?
As opções contendo hibernating, hibernated ou pausing estão incorretas simplesmente porque esses não são estados oficiais de ciclo de vida de instâncias reconhecidos pela API do Amazon EC2. Os estados oficiais são apenas: pending, running, stopping, stopped, shutting-down e terminated.

Armazenamento em Blocos (Block Storage): Os dados são divididos em "blocos" de tamanho fixo e gerenciados como discos rígidos individuais que podem ser anexados a servidores (máquinas virtuais). Rede / Metadados: "Rede" é o meio de comunicação, e "Metadados" são informações sobre os dados (usados fortemente no armazenamento de objetos), mas nenhum dos dois representa uma categoria isolada de armazenamento.

A resposta correta é: incrementais/somente os blocos no dispositivo que tiverem mudado depois do snapshot mais recente serão salvos.

Por que essa é a resposta correta?
Os backups do Amazon EBS (conhecidos como Snapshots) são incrementais por padrão. Isso significa que, se você tiver um disco de 100 GB, o primeiro snapshot fará a cópia integral desses 100 GB. Porém, se você alterar apenas 5 GB de arquivos durante o dia e fizer um novo snapshot, a AWS salvará apenas esses 5 GB que foram modificados, e não os 100 GB inteiros novamente.

Isso otimiza o tempo de execução do backup e reduz drasticamente os custos de armazenamento no Amazon S3 (onde os snapshots ficam guardados secretamente). Apesar de serem incrementais, se você precisar restaurar o disco a partir do segundo snapshot, a AWS magicamente remonta o disco inteiro de 100 GB sem nenhum problema.

Por que não as outras opções?

integrais/todos os dados são salvos toda vez...: Falso. Como explicado acima, os snapshots subsequentes não copiam tudo de novo, apenas o que mudou.

incrementais/todos os blocos no dispositivo serão salvos: Contraditório. Se todos os blocos fossem salvos, o backup seria integral (full), e não incremental.

manuais/precisam ser agendados e acompanhados diariamente...: Falso. Embora você possa fazer snapshots manuais, a AWS oferece ferramentas como o Amazon Data Lifecycle Manager (DLM) e o AWS Backup para automatizar totalmente a criação, retenção e exclusão diária de snapshots.

orientados a bancos de dados/somente instâncias EC2 que gerenciam dados...: Falso. Qualquer volume EBS anexado a qualquer tipo de instância EC2 (servidor web, servidor de arquivos, etc.) pode ter snapshots realizados, independentemente do que está armazenado lá.

# Prompt Consolidado: Análise de Experiência do Cliente (CX) para o Setor Bancário

Este documento consolida as diretrizes, o contexto e as instruções estruturadas para a execução de análises automatizadas de feedback de clientes em canais digitais bancários, utilizando IA com foco executivo.

---

## 1. Visão Geral da Análise

* **Objetivo Principal:** Analisar avaliações de clientes coletadas nas lojas de aplicativos e pesquisas de satisfação para identificar os principais pontos de dor, elogios recorrentes e causas de insatisfação no suporte digital.
* **Público / Áreas Usuárias:** Equipe de Produto, Time de Atendimento ao Cliente, Diretoria de Operações e Gerência de Atendimento.
* **Ações e Decisões Apoiadas:** Priorização do roadmap de correções de bugs, melhorias na usabilidade do aplicativo mobile de investimentos e decisões sobre investimentos em automação, treinamento de atendentes e revisão de fluxos de autoatendimento.
* **Critério de Sucesso:** Apresentar clareza nas prioridades, acionabilidade imediata para os times e forte alinhamento com a satisfação do usuário.

---

## 2. Escopo e Contexto por Canal

### 2.1. Aplicativo Mobile de Investimentos
* **Contexto:** Trabalho com feedbacks de clientes bancários voltados à experiência de investimentos via aplicativo mobile.
* **Dados Disponíveis:** Comentários textuais de usuários, data da postagem, nota de 1 a 5 estrelas, versão do aplicativo utilizada e ID anonimizado do cliente.
* **Critérios de Análise:** Classificação dos feedbacks por **sentimento**, **temas principais** e **nível de urgência**.

### 2.2. Chat no Internet Banking (Suporte Digital)
* **Contexto:** Estruturação de melhorias trimestrais na central de atendimento digital para mitigar pontos de atrito no suporte via chat.
* **Dados Disponíveis:** Relatórios anônimos de conversas de chat, incluindo transcrições textuais das mensagens, tempo de espera na fila, notas de satisfação pós-atendimento (CSAT) e categoria do assunto tratada.
* **Instruções Específicas de Análise:**
  * Classificar os feedbacks por **sentimento**, **categoria de problema** e **urgência**.
  * Identificar os principais padrões, problemas, elogios e oportunidades.
  * Apontar evidências diretamente nos dados fornecidos.
  * Sugira ações práticas para o time de operações e a gerência de atendimento.

---

## 3. Formato Esperado da Entrega

A resposta da IA deve seguir rigidamente a seguinte estrutura:
1. **Resumo Executivo estruturado** com tópicos claros.
2. **Lista estruturada de insights** priorizados por impacto.
3. **Tabela de priorização de problemas** acompanhada de recomendações acionáveis para cada problema identificado.

---

## 4. Cuidados, Restrições e Linguagem

* **Papel da IA:** Atuar estritamente como **Analista de Experiência do Cliente**.
* **Restrições de Dados:**
  * Use **apenas** os dados fornecidos.
  * Não invente números, causas ou conclusões.
  * Não exponha dados pessoais ou sensíveis.
  * Se houver informação insuficiente, indique claramente a limitação.
* **Estilo de Linguagem:** Linguagem corporativa e **executiva**.
